# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with this repository.

## What this crate does

`dsl_compiler` is the backend half of the DSL compiler: it takes resolved `.sim` IR (parsing, AST, and name resolution live in the sibling `dsl_ast` crate and are re-exported here for convenience — `dsl_compiler::{ast, parser, resolve, ir, ...}`) and lowers it through a dedicated Compute-Graph IR (`cg::*`) to WGSL compute kernels plus the Rust host-side dispatch/binding glue that runs them. Per `src/lib.rs`'s module doc, the older hand-written per-declaration-kind emitters (`emit_mask`, `emit_view*`, `emit_scoring*`, `emit_physics*`, `emit_megakernel`, etc.) were deleted in the "Phase 7 wolf-sim wipe" (2026-05-02); **the `cg::*` pipeline is the sole supported emission path today.** Every `crates/*_runtime/build.rs` and the `crates/sims` mega-crate's `build.rs` call into this crate's `build_helper::emit`/`emit_namespaced` to turn `assets/sim/<fixture>.sim` into generated Rust+WGSL at build time — this crate has no build.rs of its own; it *is* the tool other crates' build scripts call. A second, independent pipeline in this crate (`ability_lower.rs` + `ability_registry.rs`) lowers `.ability` files straight to `engine::ability::AbilityProgram`/`AbilityRegistry` runtime structs, bypassing the CG IR entirely — see "Two lowering pipelines" below.

Note this diverges from the CPU/GPU dual-backend picture in `docs/overview.md` §2 (`SerialBackend` + `GpuBackend`) and `docs/game/compiler_progress.md` (which still describes `xtask compile-dsl` and per-milestone Rust-handler emission) — both documents predate the Phase 7 wipe and compute-graph rewrite and are stale on emission-pipeline specifics. Trust the code (`src/lib.rs`'s module doc, `src/cg/mod.rs`, `src/cg/emit/mod.rs`) over those two docs for "what does this crate emit today." `docs/spec/dsl.md` §9 ("Compiler architecture") is the canonical contract and is current — read it before changing lowering or emission behavior; this file only orients you inside the source tree, it doesn't restate the spec.

## Commands specific to this crate

```bash
cargo build -p dsl_compiler
cargo test -p dsl_compiler                       # ~150 integration test files under tests/, plus unit tests inside src/*.rs
cargo test -p dsl_compiler <test_name>            # substring-matches across every test binary in tests/
cargo test -p dsl_compiler --test <file_stem>     # run just one integration-test file's tests, e.g. --test lol_corpus_lowering
```

- No golden/snapshot files are committed for emitted output. `tests/terrain_emit.rs` states why: "Goldens are *not* committed (ahash drift caveat)". Tests instead assert `rust_src.contains("...")`/`wgsl.contains("...")` substrings against emitted text, or run the emitted WGSL through `naga` (dev-dependency, pinned to `=26.0.0` to match `engine_gpu`'s dialect) to validate it parses. Follow this pattern for new emit tests rather than diffing whole-file output.
- To actually compile a `.sim` fixture end to end (not just unit-test one lowering pass), the entry point is `build_helper::emit_into` — exercised by `tests/build_helper_emits_terrain.rs` and `tests/build_helper_with_imports.rs`, and by every real fixture's `build.rs` (see `crates/sims/build.rs` and the two remaining legacy `crates/tom_probe_runtime` / `crates/viewer_runtime` build scripts). `SIM_REQUIRE_ALL_RULES=1` in the build environment promotes normally-tolerated lower diagnostics (a physics rule silently dropped from the schedule) and event-ring-ordering "Bug"-severity findings to hard build errors — off by default because most fixtures historically relied on warn-and-drop.
- Multi-file `.sim` imports resolve against `WORLDSIM_STDLIB_ROOT` (default `<workspace>/stdlib`) and `WORLDSIM_SANDBOX_ROOT` (default the workspace root) env vars — set these if testing import resolution outside the normal build-script context (`imports.rs`, `parse_with_imports`).
- Several `src/cg/**` files are very large (`emit/wgsl_body.rs` ~550KB, `emit/kernel.rs` ~420KB, `lower/expr.rs` ~260KB, `emit/program.rs` ~175KB, `lower/driver.rs` ~220KB, `well_formed.rs` ~240KB). Grep/search within these rather than reading them whole; expect this crate to dominate workspace incremental-build time.

## Internal architecture

The pipeline is `dsl_ast` (parse → AST → resolve → IR) → **this crate's `cg::*`** (CG IR → lowering → scheduling → emission), matching the four phases documented in `src/cg/mod.rs`'s module doc and `docs/superpowers/plans/2026-04-29-dsl-compute-graph-ir.md`:

1. **IR data model** (`cg/data_handle.rs`, `cg/expr.rs`, `cg/op.rs`, `cg/dispatch.rs`, `cg/program.rs`, `cg/stmt.rs`) — the `CgProgram`/`CgProgramBuilder`, typed `DataHandle`s (references into simulation state), the `CgExpr` tree, `ComputeOp`/`ComputeOpKind`, and `DispatchShape`. `cg/well_formed.rs` is the single gatekeeper pass that checks the *semantic* invariants the builder doesn't catch at insertion time: type coherence, schedule-blocking cycles, and the constitution's P6 mutation-channel rule (mask/scoring/physics/spatial-query/plumbing ops may not `Assign` an `AgentField` directly — they must `Emit` an event; only view-fold ops may write agent fields directly). It never panics — it walks potentially-malformed programs by design and returns a typed error list.
2. **Lowering** (`cg/lower/*`) — one module per declaration kind (`mask.rs`, `view.rs`, `physics.rs`, `scoring.rs`, `spatial.rs`, `terrain.rs`, `verb_expand.rs`, `param_rules.rs`, `event_binding.rs`), a shared `expr.rs` for expression lowering, and `driver.rs` as the orchestrator (`lower_compilation_to_cg[_with_opts]`) that runs them in the right order and synthesizes plumbing ops (`plumbing.rs`). Every pass returns the unified `LoweringError` enum (`error.rs`), variants prefixed by construct name (`Mask*`, `View*`, ...).
3. **Scheduling** (`cg/schedule/*`) — `topology.rs` builds the read/write dependency graph and topologically sorts it (Kahn's algorithm); `fusion.rs` groups consecutive same-dispatch-shape, non-write-conflicting ops into candidate megakernels; `strategy.rs` selects a `ScheduleStrategy` (`Conservative` / `Default` / `Megakernel`) governing how aggressively fusion applies (some fixtures, e.g. quest-arc/village-day-cycle ones, pin `Conservative` because they're incompatible with fusion); `synthesis.rs` produces the final `ComputeSchedule`/`ComputeStage`/`KernelTopology` that emit consumes; `ring_order.rs` is a separate validator that catches event-ring producer/consumer ordering bugs (a chronicle consumer scheduled before its producer silently folds nothing) — its findings are always printed as `cargo:warning`, and only `Bug`-severity ones (no cycle explains the ordering — i.e. a compiler defect, not an unavoidable fixture shape) are promotable to a hard error via `SIM_REQUIRE_ALL_RULES`.
4. **Emission** (`cg/emit/*`) — `kernel.rs`/`wgsl_body.rs` lower a `KernelTopology` to WGSL kernel bodies plus a `kernel_binding_ir::KernelSpec` (binding-graph IR shared with `kernel_lowerings.rs`, so the four downstream surfaces — Rust bind-group-layout entries, WGSL binding declarations, `BindGroupEntry` construction, and the `Bindings` struct — are structurally derived from one spec rather than hand-kept in sync); `program.rs` (`cg/emit/program.rs`, not to be confused with the IR's `cg/program.rs`) walks a full `ComputeSchedule` and assembles the deterministic `EmittedArtifacts` (`BTreeMap<filename, wgsl>` + `BTreeMap<filename, rust>` + `kernel_index` + `kernel_specs`) that `build_helper` writes to `OUT_DIR`; `invariants.rs`/`metrics.rs`/`probes.rs` are optional wrapper layers that add debug-check/telemetry/test-scaffold emission on top of the base program (`emit_cg_program_with_invariants[_and_metrics/_and_probes]`); `controls.rs`, `cross_cutting.rs`, `ui_model.rs`, `json.rs` are a separate family ("Plan A") that emit player-facing JSON descriptors matching `engine_play_api`/`engine_ui`'s serde shapes rather than WGSL/Rust (`tests/descriptor_json_roundtrip.rs` proves round-trip parity by parsing emitted JSON back through those crates' `from_json`); `spatial.rs`/`terrain.rs`/`sort_kernel.rs` are domain-specific emit helpers (spatial-grid prelude, terrain generation, GPU sort kernels); `render.rs` composes final file text. Determinism is load-bearing here: every input is structural (typed enums/arena ids), `f32` uses `{value:?}` round-trip-safe formatting, and no `HashMap` iteration order leaks into output — `wgsl_emit_is_deterministic`-style tests pin this.

**Two lowering pipelines.** `ability_lower.rs` and `ability_registry.rs` are a separate, older pipeline for `.ability` files (the ability sub-DSL, `docs/spec/ability_dsl_unified.md`) that lowers directly to `engine::ability::{AbilityProgram, EffectOp}` runtime structs and builds a frozen `AbilityRegistry` — it does not go through `cg::*` at all. `ability_registry.rs` assigns stable 1-based `AbilityId`s across files in input order, resolves `cast <Name>` references, and detects cast-dependency cycles. `cpu_chronicle_reference.rs` is a hand-written CPU reference for the GPU ability dispatcher's chronicle-record output shape — a parity anchor, not a general CPU backend. `belief_decay_wgsl.rs` similarly hand-authors one WGSL kernel (per-tick `BeliefState` decay) as a Rust function because the DSL has no `for_each_agent`-body primitive yet to express that shape declaratively.

Other top-level modules: `kernel_binding_ir.rs`/`kernel_lowerings.rs` (the shared binding-graph IR + derivations reused by `cg::emit::kernel`, described above); `schema_hash.rs` (hashes the byte content of every `// GENERATED` file to drive `crates/engine/.schema_hash` regeneration); `seq.rs` (deterministic event-sequence-number packing per constitution P11); `custom_agent_fields.rs` (a registry that lets `.sim` files declare new `field <name>: <ty>` SoA columns without touching the closed `AgentFieldId` enum — must be populated *before* resolve/lower runs, per `build_helper.rs`'s `emit_into`); `imports.rs` (multi-file `.sim` import resolution — `parse_with_imports`, cycle/collision diagnostics).

## Non-obvious things

- **Emitted-file header convention:** every generated Rust/WGSL file starts with `// GENERATED by dsl_compiler — do not edit by hand.` (exact string varies slightly by emitter, e.g. `schema_hash.rs` writes `// GENERATED by dsl_compiler. Do not edit by hand.`). The workspace pre-commit hook (`.githooks/pre-commit`, per root `CLAUDE.md`) enforces this header on generated files — don't hand-edit files carrying it, and if you add a new emitter function, copy the existing header string exactly rather than inventing a variant.
- **P6 mutation-channel rule is enforced structurally, not just by convention:** `well_formed.rs` will reject a CG program where a mask/scoring/physics/spatial-query/plumbing op directly assigns an `AgentField` — only view-fold ops may. If a new lowering pass needs to change agent state, it must emit an event, not synthesize an `Assign`.
- **`emit_namespaced` rewrites `crate::` → `super::` in generated source** so the same emitted files work both as a standalone per-fixture crate (kernel modules at crate root) and inside the `sims` mega-crate (`pub mod <fixture> { include!(...) }`, kernel modules one level down). If you add a new emitted file that references sibling generated modules, use `crate::`-relative paths and let this rewrite handle the mega-crate case — don't hardcode `super::`.
- **Lower diagnostics are tolerated by default.** A physics rule that fails to lower doesn't fail the build unless `SIM_REQUIRE_ALL_RULES=1` is set — it's dropped from the schedule with a `cargo:warning`. This was the root cause behind at least one shipped bug (Gap plague_city#P-C, cited in `build_helper.rs`) where a fixture's schedule silently shrank by 9 stages with no compile-time signal. When debugging "a rule I wrote isn't doing anything," check for a `[<fixture> lower diag]` build warning before assuming the DSL/lowering itself is broken.
- **`ScheduleStrategy::Conservative` exists specifically for fixtures incompatible with kernel fusion** (quest-arc, village-day-cycle historically) — if a new fixture's emitted kernel behaves correctly per-op but wrong once scheduled, try `emit_with_strategy(name, ScheduleStrategy::Conservative)` to isolate whether fusion is the cause before debugging the fusion pass itself.
- **`cg/program.rs` (the IR's top-level `CgProgram` type) and `cg/emit/program.rs` (full-schedule-to-`EmittedArtifacts` assembly) are different files with the same basename** — disambiguate by full path when searching or citing.
